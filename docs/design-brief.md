# Design brief — the music-stack play-along report

Design a single-page web UI: an interactive **play-along page** for a
songwriter finishing a rough demo. A local analysis tool records the song's
structure, chords, notes, and lyrics, then generates this page as **one
self-contained HTML file** the writer double-clicks, practices against, and
emails to a bandmate.

## Who uses it, and when

A songwriter — typically a guitarist who sings — at 11pm with a half-finished
song. Two postures:

1. **At the desk**: skimming what the analysis found — structure, missing
   sections, chords, lyric — deciding what to write next.
2. **At the instrument, music stand distance**: playing along. Charts must be
   legible from ~1 m; the interactive layer (playhead, current word, current
   chord) must be visible in peripheral vision while hands are busy.

Desktop browser first; tablet on a music stand is the second seat; phone
should degrade gracefully (≥375 px).

## Hard constraints (non-negotiable)

- **One HTML file, zero dependencies.** No frameworks, no CDN, no webfonts,
  no network requests at all. System font stack, inline CSS/JS/SVG, audio as
  a base64 data URI. Must work opened via `file://`.
- Generated by Python string templating — the design must be expressible as
  static markup + CSS custom properties + vanilla JS. No build step.
- All existing interactions (list below) must survive the redesign.
- Scale: songs are 1–10 min, up to ~15 sections, hundreds of notes per
  section, ~50 lyric lines. Total DOM is large; the page must stay smooth.
- Light theme required (print-adjacent, readable in a lit room). Dark mode
  optional.

## Content inventory (everything varies; all of it is optional)

- Title, BPM, duration, codec/sample-rate facts.
- Audio player (embedded preview, or a note explaining why not).
- **Section timeline**: labelled colored segments (intro/verse/chorus/bridge/
  solo/break/outro), proportional widths, clickable, with a moving playhead.
- Arrangement string (`start → intro → verse → …`) and "missing sections"
  callout (e.g. *no bridge yet*).
- **The score**: one continuous surface, one panel per section. Each panel
  has: section label chip (hue-coded by label), time range, mini chord
  progression, a hold-alt "▶ tones" button, four switchable views, and a
  folded "re-transcribe this section" command with a copy button.
- **Four views per section**, switched globally (one switcher drives every
  panel):
  1. **Piano roll** — SVG note rectangles, octave gridlines with C labels,
     velocity → opacity; a row of stacked note-name columns beneath, aligned
     to their moment (columns that would collide dim to a texture and
     re-light as the playhead passes); a lyric row beneath that.
  2. **Guitar tab** — monospace six-line tab; a neck-position selector
     (low / 5th / 9th) offering the same notes in different fingerings;
     lyric row aligned to tab columns.
  3. **Sheet music** — grand staff SVG with engraving-style spacing, treble
     and bass clefs, accidentals, ledger lines; when a beat grid exists:
     time signature, bar lines, stems, beams, flags; horizontal scroll with
     auto-follow; lyric row aligned to note columns.
  4. **Chord chart** — clickable timed chord chips plus a textbook-grip tab
     chart.
- **Source toggle: Instrument | Voice.** Every view exists twice — the
  played transcription and the sung melody. Toggle appears only when a voice
  transcription exists. Empty state: "No notes transcribed here."
- **Lyric row under every chart**: individual words placed at the moment
  they're sung, alternating between two lanes per lyric line so phrases read
  left-to-right without overlap; the current word highlights during playback.
- **Karaoke line** in the player area: the line being sung right now.
- **Chord shape cards**: SVG chord boxes (dots, open strings, muted x,
  base-fret label) with symbol + shorthand captions.
- **Lyrics as sung**: full transcript as clickable timed lines (or plain
  text when untimed), with a provenance note (isolated stem vs full mix).
- **Stems**: file list links. Note: users can drop their own Moises/Suno
  separations into `stems/user/`.
- **"To finish this"**: derived songwriting questions (bullet list).
- Footer note for skipped analysis stages, with the command that fixes them.
- Info card (behind an ⓘ button): how it was made, how to use it, accuracy
  caveats.

## The player bar (sticky, always in reach)

Keep it compact — this was recently decluttered and must stay that way:

- Audio element (native controls acceptable; better welcome).
- Section timeline with playhead.
- Karaoke line (only while a line is sung).
- View switcher (4 views) + source toggle (Instrument | Voice).
- A **"speed & keys" dropdown** holding: speed pills (0.5× / 0.65× / 0.75× /
  0.85× / 1× — time-stretch, pitch preserved) and the keyboard cheat sheet.
- Loop badge (shows "looping 0:24–0:31" when a loop is set).

## Interactions that must survive (the behavioral contract)

- `space` play/pause · `←`/`→` scrub 1 s · `[` `]` speed down/up.
- **Plain click** anywhere timed (timeline, chips, words, lines, names,
  charts) moves the playhead **without starting playback**.
- **Plain drag** across any chart scrubs the recording audibly through the
  exact time under the pointer; a paused song plays during the drag and
  re-pauses after.
- **⌘-click two spots** = A/B loop: region shades in the timeline and in
  every chart; playback and scrubbing wrap; `esc` clears.
- **⌥-click** a notehead = hear that pitch; ⌥-click beside notes = hear the
  whole moment (chords strum); **⌥-drag** = sweep through notes with held,
  cross-fading synth voices.
- **Hold ⌥** to surface each section's "▶ tones" button: plays that
  section's transcription as synth at song tempo (respects the speed pills;
  becomes "■ stop" while playing).
- During playback: playhead line in every visible chart (glides smoothly
  between note columns), current section gets an accent and auto-scrolls
  into view, staff/tab auto-scroll horizontally, current chord chip / word /
  lyric line / note-name column highlight, karaoke updates.
- Copy button on each section's lick command.

## Current visual language (starting point, not a mandate)

Warm paper ground (#f7f5f0), cards (#fffdf8), soft ink (#2a2722), terracotta
accent (#bc5a3c) reserved for the interactive/now layer, slate-blue
(#54677d) for the notes themselves, hue-coded section chips, hairline
borders, no heavy shadows. Feels editorial. You may depart from this — but
keep: a single accent meaning "now / interactive", per-section hue coding,
notes visually distinct from chrome, and music-stand legibility.

## Known weaknesses to solve (why we're asking)

- The page reads as a long stack of similar cards; hierarchy between
  "reference material" (shapes, stems, questions) and "the score you play
  from" is weak.
- Dense sections still feel busy: note-name rows, lyric lanes, and chord
  chips compete. What earns permanent visibility vs appearing on
  hover/playback?
- The four-view switcher, source toggle, and per-tab position selector are
  three separate pill clusters — unify the switching language.
- The playhead/now-highlighting is spread across many small treatments
  (line, chip fill, word growth, name growth, section bar) — design one
  coherent "now" system.
- Empty/degraded states are plain text paragraphs; make sparse analyses feel
  intentional, not broken.
- No designed print story (a printable score would be loved).

## Deliverables wanted

A visual concept covering: overall page layout and hierarchy; the sticky
player bar; one section panel in all four views (dense data, both sources);
the lyric-under-chart treatment; playhead/"now" system across views; loop
shading; hover/active/empty states; the dropdown; chord cards; mobile/tablet
behavior; and the color/type system as CSS custom properties.
